# Wumpo — CLAUDE.md

## Что это

Десктопный прототип будущей игровой консоли размером с брелок. Эмулятор — это
эталонная реализация устройства, которого ещё не существует: экран 64×32,
монохром, шесть кнопок, один пьезоизлучатель, несколько сотен байт сохранений.

Перед любым структурным изменением прочитай `docs/architecture/overview.md` и
`docs/decisions/`.

## Архитектура

```
Game → Runtime → Platform Abstraction → Desktop (SDL3) / будущий Hardware
```

Игровая логика никогда не включает заголовки SDL, Windows или ОС. Она общается с
интерфейсами `Display`, `Input`, `Audio`, `Storage` и `Clock` из `src/platform/`.
Если изменение делает `src/game` или `src/core` зависимым от бэкенда — изменение
неверно.

Проверить изоляцию можно в любой момент:

```powershell
cmake --preset ci-core   # конфигурация с WUMPO_BUILD_EMULATOR=OFF
```

Ядро, все тесты и headless-бэкенд обязаны собираться и проходить без SDL.

## Правила детерминизма — не обсуждаются

Они делают возможными replay, golden-тесты и будущие таблицы рекордов. Нарушение
любого из них — баг, даже если сегодня ничего не падает.

1. **Никакой плавающей точки в симуляции.** Позиции и скорости — целые числа или
   фиксированная точка 8.8. `float`/`double` допустимы только в масштабировании
   на стороне рендера и в генерации аудиосэмплов, но никогда в `tick()`.
2. **Никаких системных часов в симуляции.** `tick()` получает `InputState` и
   больше ничего — ни `dt`, ни timestamp. Всем временем владеет цикл с
   фиксированным шагом.
3. **Никакого `<random>`.** Распределения из стандартной библиотеки отличаются
   между реализациями. Используй `wumpo::core::Pcg32`.
4. **Никаких аллокаций в куче во время игры.** Это проверяет
   `tests/unit/test_allocations.cpp` — тест падает, если симуляция аллоцирует.
5. **Никакого обхода неупорядоченных контейнеров** так, чтобы это влияло на состояние.
6. Ввод доходит до симуляции только в виде битовой маски кнопок. Границы нажатий
   (`pressed`/`released`) вычисляются внутри runtime — поэтому replay из сырых
   масок воспроизводится точно.

## Команды

```powershell
cmake --preset debug            # конфигурация
cmake --build --preset debug    # сборка
ctest --preset debug --output-on-failure

.\scripts\dev.ps1 build         # конфигурация + сборка одной командой
.\scripts\dev.ps1 test
.\scripts\dev.ps1 run -- --demo
.\scripts\dev.ps1 format        # clang-format, на месте
.\scripts\dev.ps1 lint          # clang-tidy
```

`dev.ps1` сам находит окружение MSVC — достаточно обычного окна PowerShell.

## Коммиты

Conventional Commits: `type(scope): описание`, типы
`feat fix refactor test docs build ci perf chore style revert`.
Один коммит — одно логическое изменение, никогда не фича плюс несвязанный
рефакторинг. Не добавлять трейлеры соавторства.

Перед коммитом: `git status` → `git diff` → `git add` → `git commit` →
снова `git status`.

## Definition of Done

Код, тесты, документация при необходимости, форматирование, чистый lint, зелёный
CI, ручная проверка. Для геймплейной работы дополнительно: играбельно, работает
рестарт, работает game over, детерминировано, работает replay, нет очевидных
багов ввода.

## Безопасность

Никогда не коммитить секреты. Проекту они не нужны — CI работает без учётных
данных. См. `SECURITY.md`. Новые зависимости обосновываются по чеклисту из
`CONTRIBUTING.md` и записываются в `THIRD_PARTY.md`.

## Зоны ответственности директорий

| Путь | Ответственность |
|---|---|
| `src/core` | конфигурация, цикл с фиксированным шагом, RNG, хэширование, утилиты фиксированного размера |
| `src/renderer` | фреймбуфер, примитивы рисования, растровый шрифт |
| `src/input` | битовые маски кнопок и детекция границ нажатия |
| `src/audio` | одноканальная очередь тонов |
| `src/storage` | версионированные сохранения с контрольной суммой |
| `src/game` | игровая машина состояний и механики |
| `src/platform` | абстрактные интерфейсы; `desktop/` — бэкенд SDL3, `headless/` — тестовый бэкенд |
| `emulator` | окно, CLI, хоткеи, отладочный оверлей |
| `tests` | `unit/`, `integration/`, `game/`, `golden/` (эталоны) |
| `tools` | небольшие утилиты для разработки |

## Чего не делаем

Никаких SDK, бэкенда, аккаунтов, мультиплеера, облачных сохранений, онлайн-таблиц
рекордов, телеметрии, рекламы, монетизации, Bluetooth и Wi-Fi. Идеи, которым это
нужно, документируются в `docs/architecture/future.md`, а не реализуются.
